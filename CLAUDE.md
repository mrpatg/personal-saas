# CLAUDE.md

Guidance for AI assistants (and humans) working in this repo.

## What this is

A reusable client-portal SaaS: clients log in to see their projects, task
lists with statuses, and invoices, and pay invoices online. The owner is the
admin and creates client accounts. This codebase is the template for several
future SaaS sites, so **nothing business-specific is hardcoded** outside
`src/config/site.ts`.

## Stack

- **Astro 7** in server (SSR) mode, `output: 'server'`
- **@astrojs/cloudflare 14** adapter, deployed to **Cloudflare Workers**
- **TypeScript** (strict), **Tailwind CSS 4** (via `@tailwindcss/vite`)
- **Cloudflare D1** (SQLite) with **Drizzle ORM**; `drizzle-kit` generates migrations
- **Better Auth** (email/password; admin plugin for roles). Planned: **Stripe**, **Resend**, magic links

## Folder structure

```
src/
  config/site.ts      # ALL branding: owner, monogram, name, copy, contact email, colors, nav, home page text
  layouts/            # BaseLayout (html shell + theme), PublicLayout (marketing), AppLayout (signed-in: sidebar + mobile tab bar)
  components/         # Logo, and ui/ primitives: Button (pill), Card, StatusBadge
  data/sample.ts      # Fake data for /preview/* design pages; delete once real data exists
  pages/              # Routes. .astro = pages, .ts = API endpoints (e.g. health.ts)
  db/schema.ts        # Drizzle table definitions (single source of truth for the schema)
  db/index.ts         # getDb(): Drizzle client bound to env.DB
  lib/auth.ts         # getAuth() (Better Auth instance), ROLES (admin, client), homeFor(user)
  lib/auth-helpers.ts # form helpers: error messages, safe redirects, cookies, temp passwords
  lib/nav.ts          # signed-in navigation for the client (/app) and admin (/admin) areas
  lib/projects.ts     # project/task status labels, queries and helpers (shared by admin and client pages)
  lib/work.ts         # task comments and work entries (time/costs): money/hours parsing, totals, queries
  lib/invoices.ts     # invoice lifecycle (draft from unbilled work, edit, send, pay, void), numbering, queries
  middleware.ts       # loads the session into Astro.locals and guards /admin and /app
  styles/global.css   # Tailwind entry + brand color tokens
migrations/           # SQL migrations generated by drizzle-kit, applied by wrangler
public/               # Static files served as-is
wrangler.jsonc        # Worker name, D1 binding, compatibility settings
drizzle.config.ts     # drizzle-kit config
```

## Conventions

- **Config-driven branding.** Read the site name, copy, contact email, colors
  and nav from `src/config/site.ts`. Use theme tokens instead of raw colors:
  `primary`, `primary-foreground`, `primary-soft`, `canvas`, `surface`, `ink`,
  `muted`, `line` (e.g. `bg-primary`, `text-muted`, `ring-line`).
- **Visual style:** upscale and soft. Warm ivory canvas, forest-green primary,
  `font-display` (Instrument Serif) for headings, Inter for everything else,
  pill buttons, `rounded-3xl` cards with `shadow-soft`. Mobile first: every
  screen must work at 375px wide. Fonts are self-hosted via @fontsource.
- **Every schema change gets a migration.** Edit `src/db/schema.ts`, run
  `npm run db:generate`, commit the new file in `migrations/`, then apply it
  locally and remotely. Never edit an applied migration; add a new one.
- **Access Cloudflare bindings** with `import { env } from 'cloudflare:workers'`
  (D1 is `env.DB`). Use `getDb()` from `src/db` for queries.
- **No secrets in git.** Local secrets go in `.dev.vars` (gitignored; template
  in `.dev.vars.example`). Production secrets: `npx wrangler secret put NAME`.
- **Auth.** Better Auth endpoints live at `/api/auth/*`. Pages read the
  signed-in user from `Astro.locals.user` (set by `src/middleware.ts`). Access
  rules are in `protectedAreas` in the middleware: `/admin/*` is admins only,
  `/app/*` is any signed-in user. Public sign-up is disabled; admins create
  clients at `/admin/clients`. The first admin is created at `/setup`, which
  only works while the `user` table is empty. Forms post back to their own
  page and call `getAuth().api.*` server-side (no client JS needed). Better Auth
  table columns are in `src/db/schema.ts`; keep property names matching
  Better Auth's field names when changing them.
- **Projects and tasks.** Admins manage them at `/admin/projects` (create,
  edit, task status, reorder, delete) and each task at `/admin/tasks/[id]`.
  Clients see their own projects read-only at `/app/projects` and each task
  at `/app/tasks/[id]`; archived projects are hidden from them, and anything
  that isn't theirs returns 404. Always filter client queries by
  `project.clientId = Astro.locals.user.id`.
- **Task comments** (`task_comment`): the admin and the project's client can
  both comment on a task; the form is `src/components/CommentThread.astro`.
- **Time and costs** (`work_entry`, admin only, never shown to clients): each
  entry is time (minutes x hourly rate) or a flat expense, with the amount
  fixed in integer cents when saved. Projects have an optional default
  `hourly_rate_cents`. Currency and locale come from `site.currency` /
  `site.locale`.
- **Invoices** (`invoice`, `invoice_line`; admin at `/admin/invoices`,
  clients at `/app/invoices`). A draft for a project pulls in the billable
  work entries whose `invoice_id` is empty (time grouped per task and rate,
  one line per expense) and sets `invoice_id`/`invoice_line_id` on them, so
  work is never billed twice. Removing a line, deleting a draft or voiding an
  invoice clears those again. Drafts are admin-only and editable; sending
  assigns the next number (`site.billing.invoicePrefix` +
  running number from `firstInvoiceNumber`) and locks it. Paid is marked by
  hand until Stripe. "Overdue" is computed (sent + past due), not stored.
  Totals are stored in cents and recalculated by `recalcTotals()` whenever
  lines change; always go through `src/lib/invoices.ts` to change invoices.
  Billing details (from, address, terms, tax, payment instructions) live in
  `site.billing`. Invoice pages print cleanly (AppLayout hides its chrome
  with `print:hidden`), which is how clients save a PDF.
- Invoiced entries can't be deleted; tasks with entries can't be deleted (FK
  is `restrict`); projects with entries or invoices must be archived instead.
- After changing `wrangler.jsonc`, run `npm run cf-typegen` to refresh
  `worker-configuration.d.ts`.
- Small commits with clear messages, one working step at a time.
- Run `npm run check` (type check) before committing.

## Commands

| Task | Command |
| --- | --- |
| Install | `npm install` |
| Dev server (http://localhost:4321) | `npm run dev` |
| Type check | `npm run check` |
| Build | `npm run build` |
| Run the production build locally | `npm run preview` |
| Deploy to Cloudflare | `npm run deploy` |
| CI deploy (migrate remote D1, then deploy) | `npm run deploy:ci` |
| Generate a migration from schema changes | `npm run db:generate` |
| Apply migrations to local D1 | `npm run db:migrate:local` |
| Apply migrations to production D1 | `npm run db:migrate:remote` |
| Regenerate binding types | `npm run cf-typegen` |

Health check: `GET /health` returns `{"status":"ok","db":"ok","migrated":true}`.
If any file in `migrations/` hasn't been applied, it returns 503 with
`"migrated":false` and a `"pending"` list.

## Deployment notes

- Cloudflare Workers Builds is connected to `main` (dashboard → Worker →
  Settings → Build). Build command `npm run build`; **deploy command
  `npm run deploy:ci`**, which applies pending D1 migrations and then deploys.
  If the deploy command is plain `npx wrangler deploy`, new tables never reach
  production and pages fail with `no such table`. Every push to `main`
  deploys, so keep `main` working.
- Secrets: `BETTER_AUTH_SECRET` (set with `npx wrangler secret put`). Var:
  `AUTH_HOSTS` in `wrangler.jsonc` lists custom domains; localhost and
  `*.workers.dev` are always allowed.
- Astro sessions are disabled (`session: false` in astro.config.mjs) because
  the adapter's auto-provisioned `SESSION` KV binding breaks preview
  (non-`main`) builds. Auth keeps its own sessions in D1.
- The adapter auto-adds an `IMAGES` binding (image optimization).
- The D1 `database_id` in `wrangler.jsonc` must be the real id from
  `npx wrangler d1 create`.
